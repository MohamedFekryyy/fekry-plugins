# Interview

A short conversation before designing, so the result is what the designer wanted and not a good answer to a different brief.

## When to ask

Ask when two reasonable readings of the request would lead to visibly different designs. Otherwise start.

| Situation | Questions |
| --- | --- |
| Small edit, bug fix, or a change to one component | None |
| Review or critique | None |
| Brief already names the job, the feel, and the limits | None |
| The designer says "just do it", or nobody is there to answer | None. State the assumptions and start |
| New screen inside an existing product | One or two. The product has settled the look |
| New page, new product, redesign, or an open brief | Two to four |

## Before asking

Read everything within reach: the brief, the repo, tokens, existing screens, Figma frames, screenshots, brand docs. Cross off whatever they answer. A question the files could have answered costs the designer's trust.

Never ask about things with a sound default here: spacing, easing, radius, accessibility, breakpoints.

## The questions

Pick only the ones still open, in this order. The first two matter most.

1. **Job.** "Who lands here, and what should they do or know when they leave?" Settles the style mode, the hierarchy, and the first action.
2. **Feel.** "Which of these is closest?" Offer two or three directions written for this product, one line each, concrete enough to picture. Always leave room for a reference: "or show me one thing you'd be proud to sit next to, and tell me what in it you like." The *what* matters more than the link.
3. **Limits.** "What must stay, and what would make you reject this on sight?" Covers brand, content, stack, and taste in one go. Dislikes are often sharper than likes.
4. **The move.** "What is the one thing people should remember?" Offer what fits the product: the typography, a product scene, an interactive line figure, the photography, or nothing beyond clarity. Read [companions.md](companions.md) before offering a scene or a figure.

## How to ask

- One message, four questions at most. Use the agent's structured question tool when there is one; otherwise number them so "1b, 2a, skip 3" is a full reply.
- Put a recommended answer first in every question, with the reason in a few words. "Go with yours" must always be a valid reply.
- Write options about this product. "Calm and clinical, like a lab report someone edited for you" is an option. "Modern", "clean", and "bold" are not.
- Use a designer's words. Ask about hierarchy, tone, and density, not frameworks.
- One follow-up is allowed, one question long, only when two answers contradict each other or an answer changes the mode. After that, decide.
- One ask per question. Do not pack a product fact sheet into "limits"; use a placeholder and flag it instead.
- A skipped question is permission to decide. Never ask it again.

## Play it back

Before building, write the brief in five lines:

> **Job:** who, and what they leave with
> **Mode:** the base mode, and why
> **Feel:** the direction, in the designer's own words where possible
> **Not:** what would get it rejected
> **Move:** the one memorable thing, or "none"

Mark anything you decided for them with "(my call)". Then start; do not wait for approval. The designer can interrupt, and a visible first version beats a second round of questions.

## Whose taste wins

The designer's explicit answer beats this skill's aesthetic defaults: palette, type, mode, atmosphere. It does not beat legibility, keyboard access, contrast, or honesty. When an answer collides with one of those, say so in one line and offer the nearest version that holds.

## Close the loop

At hand-over, go back to the five lines and say how the work answers each one. If one is not met, say which and why. Then ask one question about the weakest one, such as "Is this quiet enough?", never "Any feedback?".
